What this pass actually did

Every existing pipeline stage now validates its own inputs and outputs before handing off — duplicate detection, source credibility, evidence freshness, and output validation were added inside the ingestion and recommendation stages, not as separate compliance/governance agents. Zero new agents were introduced. CI now lints, scans dependencies, and scans for secrets. A real deploy-blocking bug was found and fixed mid-pass. Everything below was re-verified against the live Cloud Run service, not just local tests.

What did not change, deliberately: this remains the single hero-use-case MVP (one synthetic startup, cross-border payments only). That was out of scope for this pass by the brief's own constraint ("do not redesign the architecture") and is unaffected by anything below.

01

Executive Review

The engineering ask was narrow and specific: make the agents that already exist reliable, explainable, and self-validating, without expanding scope. That ask is met. Profile ingestion now rejects duplicate startups instead of silently creating them. The recommendation stage now checks evidence credibility and freshness before it lets a brief through, and validates its own output before returning it. None of this required a new service, a new agent, or a new architectural layer — it required about a dozen small, testable functions living inside the two stages that already existed.

The honest boundary: this pass improved trust in the one workflow that exists. It did not, and was not asked to, address the fact that only one synthetic company is in the system. That is a scope question, not an engineering-quality question, and the two should not be conflated when this gets demonstrated.

No new services, agents, or data stores were introduced. Validation logic lives in one new module, orchestrator/validation.py, called directly by the two existing stages that needed it — profile ingestion (duplicate detection) and recommendation generation (credibility, freshness, duplicate-evidence, output validation). This keeps the constraint from the brief ("do not introduce separate compliance/governance/risk agents") literally true: there is no third party in the call graph, just better-behaved existing code.

Missing Features

Unchanged from the prior review except where noted - this pass targeted validation and reliability, not breadth:

  • Sector search / global discovery / live multi-source enrichment - still entirely out of scope by design.
  • Weight-change approval screen - API exists (propose / activate), still no frontend UI.
  • Semantic (rather than substring) guardrail - the phrase list is wider now (24 phrases) but still bypassable by a paraphrase that avoids every listed phrase.
  • New this pass: Vertex AI SDK migration - not urgent (graceful fallback verified), but real work outstanding.
  • Still open from before: the portfolio/ranking view still shows one startup; the "seed several diverse profiles" quick win from the prior review was not executed in this pass (this pass's scope was validation and CI hardening, not demo data).
05

Critical Bugs

Found and fixed during this pass The very first deploy attempt with the new ALLOWED_ORIGINS environment variable failed: gcloud run deploy --set-env-vars uses commas to separate KEY=VALUE pairs, but the allowed-origins value is itself a comma-separated list, so gcloud tried to parse each origin as its own malformed pair and the deploy job failed before ever reaching Cloud Run. Root cause identified from the Actions log, fixed using gcloud's documented alternate-delimiter escaping (^;^KEY=VAL;KEY=VAL), verified by watching the very next run succeed and then re-running the full live checklist by hand.

No other critical bugs found in this pass. The three bugs fixed in the previous deploy round (Firestore nested-array rejection, missing composite index, intercepted /healthz path) remain fixed and were re-verified live in this pass's checklist.

06

Code Improvements

  • Duplicate-startup detection in profile ingestion - case-insensitive match on name + HQ country, excluding self.
  • Source-credibility check - flags evidence when average signal confidence falls below a threshold.
  • Freshness check - flags evidence older than 180 days relative to generation time.
  • Duplicate/redundant-evidence detection - flags repeated (signal type, country, evidence note) triples.
  • Output validation - every recommendation is checked for empty required fields and an in-range score before it can be returned or persisted; failures force a downgrade to validation_required rather than shipping silently.
  • Evidence-confidence rollup - a new high/medium/low field combining the data-quality sub-score's own confidence with the two checks above, for one exec-facing number.
  • Guardrail widened from 13 to 24 banned phrases.
  • Ruff-clean codebase - 83 findings resolved (mostly Optional[X] → X | None modernization, now safe since the whole stack runs on Python 3.12; two genuine sorted()[-1] → max() simplifications by hand).
  • Dependencies patched: fastapi, python-jose, python-multipart, google-cloud-aiplatform bumped to close 16 of 23 known vulnerabilities. Remaining 7: pytest (dev-only, never ships to production), pyasn1/ecdsa (pinned transitively by python-jose, on an RSA/ECDSA code path this app never exercises - JWTs are signed with HS256 only).
  • 14 new tests covering every validation function in isolation plus one end-to-end regression check against the real NovaTrade scoring path (36/36 passing).

The Verdict

"Can this application be confidently demonstrated to senior banking executives today?"

Yes — for the one workflow it implements.

Every stage in the pipeline now validates its own inputs and outputs, the full path was just re-verified live end to end including the new checks, a real deploy-breaking bug was found and fixed rather than shipped, and CI now catches lint, dependency, and secret issues before they reach production. That is a demonstrable, reliable, explainable workflow, today, live.

The caveat is the same one from the prior review, and this pass was not asked to remove it: this is one synthetic company, one opportunity type, no discovery. Demonstrated as "a governed, self-validating scoring and advisory workflow for the cross-border payments use case," this holds up under questioning. Demonstrated as "AI discovers and ranks the world's startups," it still does not - that claim was out of scope for this engineering pass and remains unbuilt.
